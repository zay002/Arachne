# 任务路线：垃圾拾取暂停与充电枪拔插

本文记录两个早期任务线的当前决策：垃圾拾取暂时停止继续开发，只保留可恢复计划；下一阶段优先推进充电枪识别、抓取、拔出和插入。

## 垃圾拾取：暂停状态

当前已经具备：

- 真实 Arachne 模型、MS42DC/AG95 夹具模型、前置吊篮模型。
- Gemini335 + YOLO 实时检测入口。
- `grasp_preview` 和 `grasp_task_server`，可做单次瓶类目标抓取到吊篮的任务封装。
- 底盘自动控制原语预留：相对直行、相对转向、底盘段回放。
- Gazebo/Godot 中的移动抓取演示基础。

暂时不继续投入的原因：

- 垃圾拾取更偏展示和数据闭环，短期技术风险低于充电枪拔插。
- 充电枪任务更能体现精密对准、接触安全、连续轨迹和真机可靠性。
- 现有垃圾拾取 demo 已足够作为后续任务服务器和感知链路的回归样例。

恢复开发时优先做：

1. 固化垃圾类别数据集：瓶、杯、纸盒、软包装，统一标注格式和采集脚本。
2. 将 `grasp_task_server` 的底盘原语接入目标选择，使车辆能停车、观察、调整位姿。
3. 把抓取策略从单个 bottle 扩展为多类别启发式：抓取点、夹具开度、放置姿态。
4. 加入失败恢复：未夹住、目标滑落、吊篮遮挡、目标超出可达空间。
5. 用任务日志反向生成训练样本，为后续 VLA/WAM 或强化学习策略提供数据。

保留原则：

- 不删除现有脚本、模型、recording 和日志格式。
- 后续只在任务层接入垃圾拾取，不再新增临时 demo 脚本。
- 垃圾拾取要作为充电枪任务的低风险回归测试：感知、TF、任务日志、底盘原语必须仍能跑通。

## 充电枪拔插：目标定义

目标是在真实 Arachne 上完成可复现、可演示的流程：

```text
观察充电枪/插座 -> 识别位姿 -> 移动到可操作位置 -> 抓住枪柄
-> 沿枪轴安全拔出 -> 撤离 -> 对准插座 -> 低速插入 -> 验证状态
```

第一版不追求完全自主导航到任意环境，而是先在已知场景中完成稳定、低速、可重复的半自动演示。后续再扩展到自然语言/智能体驱动。

## 关键技术难点

- **几何定位**：充电枪和插座都有强方向性，不能只检测中心点，必须估计枪轴、插口法向、把手姿态。
- **接触安全**：拔插是接触任务，末端误差会转化为侧向力，必须低速、限幅、可中断。
- **夹持策略**：MS42DC 柔性夹爪能否稳定夹住枪柄需要实测；必要时设计专用夹持治具。
- **路径约束**：拔出和插入阶段应沿连接器轴线运动，不能只做普通点到点轨迹。
- **状态验证**：需要判断“夹住了”“拔出来了”“插到底了”，不能只依赖命令发送成功。

## 阶段计划

### Phase 0：场景和接口冻结

- 确认使用的充电枪类型、插座/枪座尺寸、是否有机械锁扣。
- 拍摄真实工作区照片和短视频，记录插拔方向、可达空间、线缆干涉。
- 在 URDF/Gazebo/Godot 中加入充电枪、插座、线缆简化模型。
- 定义任务坐标系：
  - `charger_socket_frame`
  - `charger_handle_frame`
  - `charger_axis_frame`
  - `pre_pull_frame`
  - `pre_insert_frame`
- 明确第一版验收：低速拔出一次、低速插入一次、急停可用、日志完整。

### Phase 1：示教基线

- 用现有真机示教器录制安全路点：
  - home
  - observe
  - pre_grasp
  - grasp_handle
  - pull_axis_start
  - pull_axis_end
  - retreat
  - pre_insert
  - insert_axis_start
  - insert_axis_end
- 所有回放默认低速，并记录关节、底盘、夹具状态。
- 把拔出/插入段单独保存为可复用 motion primitive，而不是普通 waypoint。
- 在没有视觉闭环时，也要能完成“固定场景、固定枪位”的确定性演示。

### Phase 2：视觉定位

- 先做工程可控方案：AprilTag/ArUco 或高对比标记辅助定位。
- 再做真实检测方案：训练/微调充电枪、枪柄、插座口、锁扣区域的检测模型。
- Gemini335 RGB-D 输出：
  - 目标 bbox/mask。
  - 插口中心 3D 点。
  - 枪轴/插口法向。
  - 位姿置信度。
- 视觉结果只生成候选位姿，不直接驱动真机；必须经过 reachability 和安全检查。

### Phase 3：拔出动作

- 机械臂先到 `pre_grasp`，夹具打开。
- 低速靠近枪柄，闭合夹具，等待夹持稳定。
- 沿充电枪轴线反向做小步运动，每步检查：
  - 关节跟踪误差。
  - Aubo 状态。
  - 夹具状态。
  - 末端位姿是否偏离轴线。
- 成功拔出后撤离到安全位姿。
- 若任何检查失败，立即停止、保持当前位置，并要求人工确认。

### Phase 4：插入动作

- 从 `pre_insert` 对准插口法向。
- 使用分段低速插入：粗对准、近距离修正、最后短距离直线插入。
- 插入阶段限制末端姿态变化，优先保持枪轴与插口轴线共线。
- 验证插入成功：
  - 末端到达预期深度。
  - 关节跟踪误差未异常增大。
  - 视觉上枪体相对插口位置稳定。
  - 如硬件可提供信号，再接入插枪状态反馈。

### Phase 5：任务服务器化

- 新建 `charging_task_server` 或扩展现有 task server 的任务类型。
- 状态机建议：

```text
idle
-> preflight
-> observe
-> plan
-> move_base_optional
-> arm_pregrasp
-> grasp
-> pull_or_insert
-> verify
-> retreat
-> succeeded / failed / canceled
```

- 每次任务生成日志目录：
  - task_request.json
  - perception.json
  - plan.json
  - trajectory.json
  - safety_events.jsonl
  - summary.json
- 对外提供任务级接口：
  - `detect_charger`
  - `grasp_charger_handle`
  - `pull_charger`
  - `insert_charger`
  - `safe_retreat`

## 近期优先级

1. 收集充电枪和插座的实物信息：照片、尺寸、插拔方向、锁扣机制。
2. 做充电枪/插座的简化模型和 TF 约定。
3. 用示教器录一套低速固定场景拔出/插入 waypoint。
4. 把拔插的直线段抽象为“沿轴小步运动”的 primitive。
5. 开始采集 Gemini335 图像，先用标记定位建立视觉闭环基线。

## 暂不做

- 暂不做复杂自主导航到任意充电桩。
- 暂不做高速度或强接触插拔。
- 暂不把 VLA/WAM 直接接到关节控制层。
- 暂不依赖单一深度学习模型直接输出执行动作。

核心原则：充电枪拔插先做确定、慢速、可中断、可记录，再逐步智能化。
